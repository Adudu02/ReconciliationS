# Documentation index

| Folder | What is inside | Who reads it |
|---|---|---|
| [`build-log/`](build-log/) | `BUILD-LOG.md` (English) and `BUILD-LOG-ES.md` (Español): architecture, dictionary of names and variables, and one entry per pull request; `CODEX-SESSION-8A.md` is the detailed log of one Codex session (questions, decisions, code). `exports/` holds the generated Word/PDF copies | Everyone; start here |
| [`adr/`](adr/) | Architecture decision records. One file per decision; retain dated amendments for compatible extensions; replace changed decisions with a new ADR | Developers, reviewers |
| [`requirements/`](requirements/) | BRS and SRS in English and Spanish (`.docx` and `.pdf`) | Product, reviewers |
| [`reference/`](reference/) | `bank-csv-reference-format.md` (read by tests) | Developers |
| [`diagrams/`](diagrams/) | `database/` (the as-built `*-implemented` ERD, states and security matrix), `roles/` (the design-time sequence per role; `roles/as-built/` has the interactive, as-built versions with the real paths, English and `*-es` Spanish), `architecture/` (as-built container diagram, interactive HTML), `flows/` (request, import-to-reconciliation, matching pipeline, SAT check and review-decision flows, interactive HTML; `*-es` files are the Spanish versions) and `progress/` (generated status map) | Everyone |

Related: the scope and task list live in `openspec/changes/mvp-reconciliation-core/` (source of truth).

## Safe-handling rules

- Move files with `git mv`; delete only after `grep -rn "<file name>" .` shows nothing depends on it. Tests read
  `docs/adr/`, `docs/reference/` and `docs/build-log/`.
- Edit the Markdown sources, never the exports. Regenerate `build-log/exports/*.docx|pdf` after changing a log (`tools/md_to_docx.js`, command in the build log section 8).
- `diagrams/database/*-implemented*` is generated by `python3 tools/db_diagrams.py` (add `--lang es`); update `TABLES` in the script when a migration changes the schema.
- `diagrams/architecture/system-as-built.html` is generated from its `.architecture.json` with the archify skill (`validate`, then `deliver`); edit the JSON, never the HTML. Update it when a container, queue, role boundary or implemented external call changes.
- `diagrams/flows/*.html` are generated from the `*.sequence.json` / `*.workflow.json` next to them with the archify skill (`validate`, then `deliver`); edit the JSON, never the HTML, and keep them in step with the flows described in the build log.
- `diagrams/progress/` is generated by `python3 tools/progress_diagram.py` (add `--lang es` for Spanish); do not hand-edit.
- Use only synthetic or anonymised data in anything stored here.
