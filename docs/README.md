# Documentation index

| Folder | What is inside | Who reads it |
|---|---|---|
| [`build-log/`](build-log/) | `BUILD-LOG.md` (English) and `BUILD-LOG-ES.md` (Español): architecture, dictionary of names and variables, and one entry per pull request. `exports/` holds the generated Word/PDF copies | Everyone; start here |
| [`adr/`](adr/) | Architecture decision records. One file per decision; retain dated amendments for compatible extensions; replace changed decisions with a new ADR | Developers, reviewers |

| [`reference/`](reference/) | `bank-csv-reference-format.md` (read by tests) and `01-conciliacion-cfdi.md` (project brief with reading links) | Developers |
| [`diagrams/`](diagrams/) | `database/` (design-time ERD and states, plus the as-built `*-implemented` ERD, states and security matrix), `roles/` (sequence per role), `architecture/` (as-built container diagram, interactive HTML) and `progress/` (generated status map) | Everyone |

Related: the scope and task list live in `openspec/changes/mvp-reconciliation-core/` (source of truth).

## Safe-handling rules

- Move files with `git mv`; delete only after `grep -rn "<file name>" .` shows nothing depends on it. Tests read
  `docs/adr/`, `docs/reference/` and `docs/build-log/`.
- Edit the Markdown sources, never the exports. Regenerate `build-log/exports/*.docx|pdf` after changing a log (`tools/md_to_docx.js`, command in the build log section 8).
- `diagrams/database/*-implemented*` is generated by `python3 tools/db_diagrams.py` (add `--lang es`); update `TABLES` in the script when a migration changes the schema.
- `diagrams/architecture/system-as-built.html` is generated from its `.architecture.json` with the archify skill (`validate`, then `deliver`); edit the JSON, never the HTML. Update it when a container, queue, role boundary or implemented external call changes.
- `diagrams/progress/` is generated by `python3 tools/progress_diagram.py` (add `--lang es` for Spanish); do not hand-edit.
- Use only synthetic or anonymised data in anything stored here.
